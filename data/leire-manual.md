# 레이레 추천 운영 매뉴얼

이 파일은 `data/leire.md`의 작성·검수·갱신 운영 규칙을 보관한다. Discord Worker가 읽는 실제 시즌 추천 답안지는 `data/leire.md`에만 기록한다.

## 추천 대상 범위 — 확정

`/추천`은 Festival Playlist 전체 콘텐츠를 대상으로 하지 않는다. 매주 차량 추천을 만드는 대상은 아래 **3개 이벤트만**이다.

1. **도전**
2. **레이스 1**
3. **레이스 2**

추천 대상에서 제외한다:

- PR 스턴트
- 일반 타임어택 / 라이벌류
- 그 밖에 위 3개 이벤트가 아닌 주간 콘텐츠

따라서 `data/leire.md`의 `현재 시즌 추천`에는 원칙적으로 **도전 / 레이스 1 / 레이스 2 세 이벤트만 기록**한다. 제외 콘텐츠에 대해 차량 추천을 임의로 추가하지 않는다.

## 운영 지침

- `data/leire.md`는 Discord `/추천`이 읽을 **확정 추천 답안지**다. 분석 중간 결과나 임시 후보는 실제 운영 데이터로 기록하지 않는다.
- 목요일 주간 Festival 자동화는 공식 Playlist 확인과 1차 브리핑/초안 생성까지만 담당한다. 자동화가 `data/leire.md`를 직접 확정·수정하지 않는다.
- 자동화 결과가 나온 뒤 주간 페스티벌 전문 채팅에서 사용자와 GPT가 이벤트별 제한, 코스, 최신 차량 아카이브와 코스 DB를 다시 검수한다.
- 최종 확정 직전에는 필요한 경우 최신 `cars`와 `courses`를 다시 읽어 오전 자동화 시점 이후의 차량 추가·수정이나 코스 변경을 반영한다.
- 이벤트별 추천은 **최대 1~3픽**의 순위형으로 정한다. 1픽이 최우선 추천이며 2픽·3픽은 추천 가치가 있을 때만 추가한다. 후보가 부족하거나 추천 가치가 낮으면 억지로 3대를 채우지 않는다.
- 각 픽은 단순 기록 순위가 아니라 이벤트 제한, 실제 코스 성격, 차량 성능, `concept`/`summary`/`tuneNotes`까지 검수한 최종 실전 추천으로 본다.
- 사용자와 GPT의 검수가 끝나고 사용자가 최종 확정을 명시한 뒤에만 실제 운영용 현재 시즌 추천을 갱신한다.
- 게시 뒤 새 튠이 추가되거나 기존 추천을 재검토할 필요가 생기면 영향받는 이벤트만 다시 검수하고, 다시 합의한 뒤 갱신한다. 자동으로 추천 순위를 뒤집지 않는다.
- Discord Worker는 추천 판단을 재구현하지 않고 `data/leire.md`의 확정 결과만 읽어 표시한다.

## `data/leire.md` 작성 원칙

- 파일명은 항상 `data/leire.md` 하나로 유지한다.
- 시즌 날짜/기준 주차/갱신 시각은 파일명에 붙이지 않고 본문의 `현재 시즌 메타` 값으로 기록한다.
- 갱신 전에 항상 최신 `data/leire.md`를 먼저 읽고 기존 구조를 유지한 채 현재 시즌 값으로 교체한다.
- 운영 지침, 분석 중간 메모, 긴 작업 설명은 `data/leire.md`에 섞지 않는다. 이런 내용은 이 매뉴얼이나 전문 채팅/공용 컨텍스트에 둔다.
- Worker parser가 안정적으로 읽을 수 있도록 기존 Heading과 고정 키 구조를 임의로 새 형식으로 바꾸지 않는다.
- `현재 시즌 추천` 아래에는 추천 대상인 **도전 / 레이스 1 / 레이스 2**만 둔다.
- 각 이벤트는 실제 추천 가치에 따라 1픽만 있을 수도 있고 2픽 또는 3픽까지 있을 수도 있다.

## 테스트 / 파서 운용 메모

- `상태: test` 데이터는 실전 최종 추천으로 간주하지 않는다.
- 테스트 데이터도 실제 최종 추천처럼 이벤트 제한, 코스, Tune ID, 차량, className, shareCode, 실제 수준의 추천 이유를 채워 **완성형 데이터 구조**를 검증한다.
- 현재 테스트 데이터는 추천 개수가 서로 다른 이벤트를 포함해 1~3픽 가변 구조를 파서가 처리할 수 있는지 검증하는 용도로 사용한다.
- 2픽·3픽이 없는 경우도 정상 데이터로 처리해야 하며, Worker가 빈 픽을 요구하거나 억지로 생성하면 안 된다.
- 추천 대상 외 PR 스턴트나 일반 타임어택/라이벌 항목이 `data/leire.md`에 없어도 정상이다.
- `data/leire.md`는 가능한 한 시즌 메타와 이벤트별 확정 추천 데이터만 유지해 Worker 파서를 단순하고 안정적으로 만든다.
